# appmeta

The identity of the binary you are building: its name, environment prefix, on-disk directory names, and where its database lives.

```go
import "github.com/khanakia/voltkit/appmeta"
```

## Why this exists

Every one of these values shows up in a dozen places — help text, env lookups, path resolution, error hints, the installer, the Homebrew formula. Centralizing them means scaffolding a new project rewrites **one file**, and every other package in the kit stays app-agnostic by taking a `Meta` as a parameter instead of importing a hardcoded name.

> **Invariant:** no package in this kit may hardcode an app name. If a package needs one, it accepts a `Meta` — or, better, just the one field it actually reads. See [`version`](../../../version) for the narrow case and [`appdir`](../../../appdir) for the wide one.

## Usage

```go
var meta = appmeta.Meta{
	Name:       "acme",
	Binary:     "acme",
	EnvPrefix:  "ACME",           // -> ACME_DB, ACME_READ_ONLY, ...
	DirName:    ".acme",          // per-project state dir, discovered by walking up
	DBFilename: "acme.db",
	DBLocation: appmeta.LocationProjectLocal,
	DocsURL:    "https://github.com/acme/acme/blob/main/docs/errors",
}
```

`appmeta.Default` is this template's own identity. Scaffolding a new project replaces that block and nothing else in the kit.

## Database location policy

`DBLocation` is a **policy**, never a baked path. Resolution happens at runtime in [`appdir`](../../../appdir).

| Constant | Behaviour | Use when |
|---|---|---|
| `LocationProjectLocal` | walks up from the working directory looking for `DirName`, the way git finds `.git` | state belongs to a repository |
| `LocationUserGlobal` | one database per user under `os.UserConfigDir()/<Name>/` | state is about the user, not a checkout |
| `LocationBoth` | project-local first, user-global fallback | the tool has both kinds of state |

```go
if !meta.DBLocation.Valid() {
	return fmt.Errorf("unknown DBLocation %q", meta.DBLocation)
}
```

`Valid()` exists so a hand-edited or mis-generated value fails loudly instead of silently falling through to a default at runtime.

## Why never bake an absolute path

A tempting shortcut is to stamp the database path in at build time:

```go
// DON'T
-ldflags "-X main.dbPath=~/app/acme.db"
```

Go performs no tilde expansion, so this creates a directory literally named `~`. Expanding it on CI instead bakes `/home/runner/...` into every user's binary. Bake the policy; resolve the path.

## Roadmap

Hand-written today. Once a `volt.yaml` manifest exists this becomes `appmeta.gen.go`, generated by `task gen` with a CI drift check. The exported surface is designed to survive that switch unchanged.
